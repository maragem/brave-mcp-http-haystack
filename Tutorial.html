How this deployment works

Unlike a custom Python server, this deployment wraps the official Brave npm package (@brave/brave-search-mcp-server) without modifying its code. Two processes run inside one Docker container:

Internet / Haystack ──▶ proxy.mjs  ← Bearer auth check · public port $PORT
│   valid token
▼
@brave/brave-search-mcp-server  ← internal only · 127.0.0.1:3100
│
▼
Brave Search API  ← authenticated with BRAVE_API_KEY

proxy.mjs uses only Node.js built-in modules — no extra npm packages needed for auth. SSE streaming is fully preserved by piping the response directly without buffering.

Two API keys — what each one does

Variable What it is Railway Haystack
BRAVE_API_KEY Your Brave Search API key — authenticates requests to Brave's search service ✓ yes ✗ no
MCP_API_KEY Bearer token you generate — protects your MCP server endpoint from unauthorised access ✓ yes ✓ yes
ℹ️
Haystack only needs MCP_API_KEY. It talks to your proxy, not to Brave directly. BRAVE_API_KEY lives exclusively in Railway and is never exposed to clients.

What's in the server — all 6 tools

All tools come from the official Brave MCP server — this deployment adds no custom tools.

brave_web_search
General web search with filtering, pagination, freshness controls, and optional AI summary key generation.
brave_news_search
News articles with freshness defaults to last 24h. Supports pagination and breaking news indicators.
brave_local_search
Businesses, restaurants, and services with ratings, hours, and addresses. Falls back to web if no local results. pro
brave_video_search
Video results with metadata and thumbnail information. Up to 50 results per page.
brave_image_search
Image search returning URLs (not base64 since v2). Up to 200 results per page.
brave_summarizer
AI-powered summary of web search results. First call brave_web_search with summary: true, then use the returned key here. pro
⚠️
Tools marked pro require a Brave Search Pro plan API key. On the Free plan (2,000 queries/month), only brave_web_search, brave_news_search, brave_video_search, and brave_image_search are fully available.

Before you start — get your Brave API key

  • 1
    Go to brave.com/search/api and sign up for an account.
  • 2
    Choose a plan. The Free plan gives 2,000 queries/month and is enough to get started.
  • 3
    Go to the developer dashboard → API Keys → generate a new key.
  • 4
    Copy the key — you will need it in Step 5 when setting Railway variables.
💡
Keep your Brave API key safe. It is set only in Railway and never passed to Haystack or any other client.

Set up your local project

Your project folder should contain exactly these files:

brave-mcp-http/
  ├── proxy.mjs ← auth proxy (pure Node.js, no extra deps)
  ├── start.sh ← starts Brave server + proxy
  ├── package.json ← single npm dep: @brave/brave-search-mcp-server
  ├── Dockerfile ← Node 20 slim container
  ├── railway.json ← Railway config-as-code
  ├── README.md ← documentation
  └── .gitignore

Verify it runs locally

terminal 
# Install the Brave MCP server package
npm install

# Set your keys (required to run)
export BRAVE_API_KEY="your-brave-api-key"
export MCP_API_KEY="your-test-token"    # optional locally

# Start both processes
sh start.sh

You should see both processes start:

[start] Starting Brave MCP server on internal port 3100 ...
[start] Brave MCP server PID: 12345
[brave] Streamable HTTP server listening on 127.0.0.1:3100
[start] Starting auth proxy on public port 8080 ...
[proxy] Listening on 0.0.0.0:8080
[proxy] Forwarding to 127.0.0.1:3100
Press CTRL+C to quit
ℹ️
The MCP endpoint is at http://localhost:8080/mcp. A health check is at http://localhost:8080/health — always public, no token needed.

Push to GitHub

Railway deploys directly from a GitHub repo. Every push to main triggers an automatic redeploy.

terminal 
cd brave-mcp-http
git init
git add .
git commit -m "Brave Search MCP server — Railway deployment"

git remote add origin https://github.com/YOUR_USERNAME/brave-mcp-http.git
git branch -M main
git push -u origin main
⚠️
Make sure .gitignore is in place. Never commit node_modules/ or any .env files. Your API keys must live only in Railway Variables.
5

Deploy on Railway & set variables

  • 1
    Go to railway.app → sign in → click New Project.
  • 2
    Select "Deploy from GitHub repo". Authorise Railway if prompted.
  • 3
    Select brave-mcp-http from your repo list → click Deploy Now. Railway detects the Dockerfile automatically.
  • 4
    Go to your service → Variables tab and add both keys:
Railway Variables tab
BRAVE_API_KEY  =  BSA...        # your Brave Search API key
MCP_API_KEY    =  generated token  # see below

Generating MCP_API_KEY

terminal 
python -c "import secrets; print(secrets.token_urlsafe(32))"
# or
node -e "const c=require('crypto');console.log(c.randomBytes(32).toString('base64url'))"
  • 5
    Once deployed, go to the service → Settings → Networking → Generate Domain to get your public URL.

Verify the deployment

terminal 
# Health check — always public, no token needed
curl https://YOUR-DOMAIN.up.railway.app/health

# Without token → 401
curl -I https://YOUR-DOMAIN.up.railway.app/mcp

# With token → 200
curl -I https://YOUR-DOMAIN.up.railway.app/mcp \
  -H "Authorization: Bearer YOUR-MCP-API-KEY"

# Explore all 6 tools in the MCP Inspector
npx @modelcontextprotocol/inspector https://YOUR-DOMAIN.up.railway.app/mcp \
  --header "Authorization: Bearer YOUR-MCP-API-KEY"

The health endpoint returns {"status":"healthy","service":"brave-search-mcp","auth":true}. The MCP Inspector lets you call all 6 tools interactively against the live Brave Search API.

ℹ️
If the /health check returns 200 but /mcp returns 502, the Brave server process hasn't finished starting yet. Wait 5 seconds and retry — start.sh waits 2 seconds before launching the proxy, but a cold Railway start can take a moment longer.

Connect to Claude Desktop

Locate your config file

paths
# macOS
~/Library/Application Support/Claude/claude_desktop_config.json

# Windows
%APPDATA%\Claude\claude_desktop_config.json

Add the MCP server entry

claude_desktop_config.json 
{
  "mcpServers": {
    "brave-search": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://YOUR-DOMAIN.up.railway.app/mcp",
        "--header",
        "Authorization: Bearer YOUR-MCP-API-KEY"
      ]
    }
  }
}

Restart Claude Desktop after saving. All 6 Brave Search tools will appear in the tools panel.

Connect to Haystack Enterprise

Use MCPToolset with StreamableHttpServerInfo in your pipeline YAML. Only MCP_API_KEY is needed here — not BRAVE_API_KEY.

1. Add the secret to Haystack Enterprise Platform

Go to Settings → Secrets and add MCP_API_KEY with the same token value you set in Railway.

2. Add the toolset to your Agent pipeline

pipeline.yaml 
- type: haystack_integrations.tools.mcp.MCPToolset
  data:
    server_info:
      type: haystack_integrations.tools.mcp.mcp_tool.StreamableHttpServerInfo
      url: https://YOUR-DOMAIN.up.railway.app/mcp
      timeout: 60
      token:
        type: env_var
        strict: true
        env_vars:
        - MCP_API_KEY
    tool_names:
    - brave_web_search
    - brave_news_search
    - brave_local_search
    - brave_video_search
    - brave_image_search
    - brave_summarizer
    eager_connect: false
⚠️
If you are on the Brave Free plan, remove brave_local_search and brave_summarizer from tool_names to avoid errors when the Agent calls them.
ℹ️
Token summary: MCP_API_KEY goes in both Railway Variables and Haystack Secrets — same value in both places. BRAVE_API_KEY goes only in Railway Variables.
